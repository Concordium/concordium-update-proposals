CIS-8004: Agent Registry¶

Created

May 22, 2026

Draft

May 25, 2026

Supported versions
Smart contract version 1 (concordium-std v10+) with concordium-cis2

Standard identifier

CIS-8004

Related
ERC-8004 v2 (Trustless Agents — Identity Registry)
CIS-0: Standard Detection, CIS-2: Concordium Token Standard 2, CIS-8: External Key Registry Standard

Abstract¶

A standard interface for an Agent Registry contract that records the identity of autonomous software agents as transferable CIS-2 NFTs.

CIS-8004 is the Concordium implementation of the Identity Registry component of ERC-8004 v2 (Trustless Agents). The Reputation Registry and Validation Registry components of ERC-8004 v2 are out of scope for this version.

Each agent is identified on chain by a 64-bit token id. The canonical off-chain identifier is the CIS-2 token address (Base58Check encoding of (version=0x02, ULEB128(index), ULEB128(subindex), TokenIdU64 bytes)).

Each agent record carries an optional external_reference that points at a CIS-8: External Key Registry Standard cryptographic-key binding (Cis8 variant); the enum may be extended with additional variants in future versions of this standard.

Introduction¶

CIS-8004 is the on-chain registry that mints a CIS-2 NFT for each agent and records:

  • A pointer to the agent’s off-chain card (agent_uri + metadata_hash).

  • An optional external_reference proving control of an off-chain identity.

  • A payment-routing field (agent_wallet) with its own independent lifecycle from CIS-2 ownership.

  • An open key/value metadata map.

CIS-8004 mirrors ERC-8004’s Identity Registry as closely as Concordium chain semantics allow. Section Departures from ERC-8004 v2 summarises the deliberate differences.

Terminology and Conventions¶

The key words “MUST”, “MUST NOT”, “REQUIRED”, “SHALL”, “SHALL NOT”, “SHOULD”, “SHOULD NOT”, “RECOMMENDED”, “MAY”, and “OPTIONAL” in this document are to be interpreted as described in RFC 2119.

Relationship to Other CIS Standards¶

  • CIS-0: Standard Detection — CIS-8004 contracts MUST advertise support for CIS-0, CIS-2, and CIS-8004.

  • CIS-2: Concordium Token Standard 2 — CIS-8004 agent NFTs are CIS-2 tokens. CIS-2 transfer, balance, operator, and token-metadata entrypoints are inherited; the transfer entrypoint additionally runs two CIS-8004 reset hooks (see transfer (CIS-2) — dual-reset hook).

  • CIS-8: External Key Registry Standard — Agents MAY carry a external_reference of variant Cis8(_) pointing at a CIS-8 cryptographic-key registration. The CIS-8004 contract verifies the binding at mint time via a cross-contract ownerOfKey call.

Specification¶

Common Types¶

AgentTokenId¶

pub type AgentTokenId = TokenIdU64;
pub type AgentTokenAmount = TokenAmountU8;  // always 1 for NFTs

AgentTokenId uses the standard CIS-2 TokenIdU64 wire form ([u8 length=8][8 LE bytes], 9 bytes total) on every entrypoint — both CIS-8004-native (agentOf, setAgentURI, …) and CIS-2 inherited (transfer, balanceOf, tokenMetadata). See Token ID Wire Format.

ExternalKeyId¶

Imported from CIS-8: External Key Registry Standard. The CIS-8004 contract MUST define a byte-compatible local copy of this type:

#[derive(Serialize, SchemaType, Clone, PartialEq, Eq, Debug)]
pub struct ExternalKeyId {
    pub namespace:  String,
    pub key_type:   String,
    pub public_key: Vec<u8>,
}

ExternalIdentifier¶

For verifier-anchored external-identifier bindings (e.g. social-media handles bound to a Concordium account by an off-chain verifier):

#[derive(Serialize, SchemaType, Clone, PartialEq, Eq, Debug)]
pub struct ExternalIdentifier {
    pub namespace:       String,
    pub identifier_type: String,
    pub identifier:      Vec<u8>,
}

Note

The field name is identifier_type, not id_type. Schema-driven serialisers reject payloads with id_type as an unknown field.

ExternalRefKind¶

#[derive(Serialize, SchemaType, Clone, PartialEq, Eq, Debug)]
pub enum ExternalRefKind {
    Cis8(ExternalKeyId),
    // Additional variants may be added in future versions.
}

The Cis8 variant points at a CIS-8: External Key Registry Standard cryptographic-key registration.

ExternalReference¶

#[derive(Serialize, SchemaType, Clone, PartialEq, Eq, Debug)]
pub struct ExternalReference {
    pub contract_address: ContractAddress,
    pub kind:             ExternalRefKind,
}

The contract MUST validate contract_address against the configured state.cis8_contract. A mismatch MUST reject with Reject Codes.

AgentStatus¶

#[derive(Serialize, SchemaType, Clone, Copy, PartialEq, Eq, Debug)]
pub enum AgentStatus {
    Active,
    Revoked,
}

MetadataEntry¶

#[derive(Serialize, SchemaType, Clone, Debug)]
pub struct MetadataEntry {
    pub key:   String,
    pub value: Vec<u8>,
}

Each key MUST be non-empty and MUST NOT exceed 64 bytes. Each value MUST NOT exceed 1024 bytes. The key "agentWallet" is reserved (see agentWallet — reserved metadata key).

AgentRecord (on-chain)¶

#[derive(Serial, DeserialWithState, Clone)]
#[concordium(state_parameter = "S")]
pub struct AgentRecord<S: HasStateApi> {
    pub agent_uri:          Option<String>,
    pub metadata_hash:      Option<[u8; 32]>,
    pub external_reference: Option<ExternalReference>,
    pub agent_wallet:       Option<AccountAddress>,
    pub status:             AgentStatus,
    pub registered_at:      Timestamp,
    pub revoked_at:         Option<Timestamp>,
    pub revocation_reason:  Option<String>,
    pub on_chain_metadata:  StateMap<String, Vec<u8>, S>,
}

The owner_account is not stored on the record; it is derived from the CIS-2 ownership state (cis2_state.token_owner(token_id)) at query time.

The agent_wallet is stored. It has an independent lifecycle from CIS-2 ownership: initialised to Some(sender) on register, updated via setAgentWallet with cryptographic proof, and reset to None on every CIS-2 transfer.

AgentView (returned)¶

#[derive(Serialize, SchemaType)]
pub struct AgentView {
    pub token_id:           AgentTokenId,
    pub owner_account:      AccountAddress,  // derived from CIS-2
    pub agent_uri:          Option<String>,
    pub metadata_hash:      Option<[u8; 32]>,
    pub external_reference: Option<ExternalReference>,
    pub agent_wallet:       Option<AccountAddress>,
    pub status:             AgentStatus,
    pub registered_at:      Timestamp,
    pub revoked_at:         Option<Timestamp>,
    pub revocation_reason:  Option<String>,
}

Token ID Wire Format¶

This section is normative. AgentTokenId is an alias for concordium_cis2::TokenIdU64, with the on-the-wire encoding [u8 length=8][8 LE bytes] (9 bytes total). Every CIS-8004 entrypoint that takes a token_id parameter — both CIS-8004-native (agentOf, setAgentURI, setExternalReference, setAgentWallet, getAgentWallet, setMetadata, getMetadata, revoke) and CIS-2 inherited (transfer, balanceOf, tokenMetadata) — MUST use this single wire form. Schema-driven JSON renders it as a hex string of 16 characters (e.g. "0a00000000000000" for token_id = 10).

Event payloads carrying a token_id field MUST use the same TokenIdU64 wire form: CIS-8004-native events (tags 240..247) and CIS-2 inherited events (tags 251..255) are byte-compatible on the token_id field. From one register transaction the same bytes appear in both events:

fe 08 0a00000000000000 ...   ← tag 254 (CIS-2 Mint)
f0 08 0a00000000000000 ...   ← tag 240 (CIS-8004 Registered)

Contract State¶

The following is an example state layout. Implementations MAY organise state differently provided they satisfy the behavioural requirements of this specification.

#[derive(Serial, DeserialWithState)]
#[concordium(state_parameter = "S")]
pub struct State<S: HasStateApi> {
    /// CIS-8 registry contract address.
    pub cis8_contract: ContractAddress,

    /// Agent records keyed by token_id.
    pub agents: StateMap<AgentTokenId, AgentRecord<S>, S>,

    /// Reverse lookup: (namespace, identifier-or-public-key bytes) -> token_id.
    pub refs_index: StateMap<(String, Vec<u8>), AgentTokenId, S>,

    /// Next token_id to assign.
    pub next_token_id: u64,

    /// CIS-2 ownership / operator state.
    pub cis2_state: Cis2State<AgentTokenId, AgentTokenAmount, S>,
}

A token_id MUST appear in refs_index if and only if its agent record has an Active status and a Some external_reference. revoke and the transfer hook (transfer (CIS-2) — dual-reset hook) MUST release the index entry.

Entrypoints¶

register¶

#[derive(Serialize, SchemaType)]
pub struct RegisterParams {
    pub agent_uri:          Option<String>,
    pub metadata_hash:      Option<[u8; 32]>,
    pub external_reference: Option<ExternalReference>,
    pub initial_metadata:   Vec<MetadataEntry>,
}
Authorisation

The sender MUST be an account (Address::Account(_)). Contract callers MUST be rejected with Reject Codes.

Validation

The contract MUST:

  1. Validate agent_uri length ≤ 4096 bytes (allows data: URIs).

  2. Validate every initial_metadata entry per MetadataEntry. Reject any entry with key == "agentWallet" with Reject Codes.

  3. If external_reference is Some, check uniqueness in refs_index; reject with Reject Codes if already held by another agent.

Effect

Assign token_id = state.next_token_id; increment the counter. Mint one CIS-2 NFT to the sender (emits CIS-2 Mint). Insert the AgentRecord with status = Active, agent_wallet = Some(sender), registered_at = ctx.metadata().slot_time(), and each initial_metadata entry inserted into on_chain_metadata. If external_reference is Some, insert the corresponding refs_index entry. Emit Registered (tag 240).

Return

AgentTokenId (the newly minted token id).

setAgentURI¶

#[derive(Serialize, SchemaType)]
pub struct SetAgentURIParams {
    pub token_id:      AgentTokenId,
    pub agent_uri:     Option<String>,
    pub metadata_hash: Option<[u8; 32]>,
}
Authorisation

Sender MUST equal the current CIS-2 token owner; otherwise reject with Reject Codes.

Validation

Reject if the agent is Revoked with Reject Codes. Validate agent_uri length per register.

Effect

Replace agent_uri and metadata_hash (each Some value replaces; None MAY be a documented “leave unchanged” or “clear” semantic — implementations MUST pick one and document it). Emit URIUpdated (tag 241).

setExternalReference¶

#[derive(Serialize, SchemaType)]
pub struct SetExternalReferenceParams {
    pub token_id:           AgentTokenId,
    pub external_reference: Option<ExternalReference>,
}
Authorisation

Sender MUST equal the current CIS-2 owner. Reject if the agent is Revoked with Reject Codes.

Effect

If external_reference is Some, check refs_index uniqueness; reject with Reject Codes if already held by another agent. Release any previous refs_index entry, set the new value, and insert the new index entry. Emit ExternalReferenceSet (tag 242).

setAgentWallet¶

#[derive(Serialize, SchemaType)]
pub struct SetAgentWalletParams {
    pub token_id:   AgentTokenId,
    pub new_wallet: AccountAddress,
    pub deadline:   Timestamp,
    pub signature:  Vec<u8>,         // flat byte array
}
Authorisation (dual)

Both of the following MUST hold:

  1. ctx.sender() equals the current CIS-2 token owner; otherwise reject with Reject Codes.

  2. signature verifies against new_wallet’s on-chain credentials over the setAgentWallet — canonical signed message bytes; otherwise reject with Reject Codes.

Validation

Reject if the agent is Revoked (Reject Codes). Reject if ctx.metadata().slot_time() > deadline (Reject Codes).

Effect

Set agent_wallet = Some(new_wallet). Emit AgentWalletSet (tag 245) with new_wallet = Some(new_wallet).

setAgentWallet — canonical signed message¶

The contract reconstructs the exact bytes the off-chain signer signed and verifies the signature against them. The off-chain signer MUST produce these bytes verbatim.

fn set_agent_wallet_signing_bytes(
    token_id:         AgentTokenId,
    new_wallet:       AccountAddress,
    deadline:         Timestamp,
    contract_address: ContractAddress,
    genesis_hash:     HashSha2256,
) -> Vec<u8> {
    let mut bytes = Vec::new();
    bytes.extend_from_slice(b"CIS-8004/v1/setAgentWallet");  // 26 bytes UTF-8
    token_id.serial(&mut bytes).expect("ser");                // 8 bytes
    new_wallet.serial(&mut bytes).expect("ser");              // 32 bytes
    deadline.serial(&mut bytes).expect("ser");                // 8 bytes
    contract_address.serial(&mut bytes).expect("ser");        // 16 bytes
    bytes.extend_from_slice(genesis_hash.as_ref());           // 32 bytes
    bytes
}

Total payload size: 122 bytes. The 26-byte UTF-8 prefix provides domain separation; contract_address and genesis_hash pin the signature to a single contract instance on a single network.

The contract MUST retrieve contract_address via ctx.self_address() and genesis_hash via ctx.metadata().genesis_hash(). Neither value may be supplied as a parameter.

revoke¶

#[derive(Serialize, SchemaType)]
pub struct RevokeParams {
    pub token_id: AgentTokenId,
    pub reason:   Option<String>,
}
Authorisation

Sender MUST equal the current CIS-2 owner.

Effect

Set status = Revoked, revoked_at = Some(now), revocation_reason = reason, external_reference = None, agent_wallet = None. Release any refs_index entry. The NFT is NOT burned. Emit Revoked (tag 244).

Reject if already Revoked with Reject Codes.

setMetadata¶

#[derive(Serialize, SchemaType)]
pub struct SetMetadataParams {
    pub token_id: AgentTokenId,
    pub key:      String,
    pub value:    Vec<u8>,
}
Authorisation

Sender MUST equal the current CIS-2 owner.

Validation

Reject if the agent is Revoked. Reject the reserved key "agentWallet" with Reject Codes. Reject out-of-range key/value sizes with Reject Codes.

Effect

Insert / replace on_chain_metadata[key] = value. Emit MetadataSet (tag 243).

getMetadata¶

#[derive(Serialize, SchemaType)]
pub struct GetMetadataParams {
    pub token_id: AgentTokenId,
    pub key:      String,
}

// returns Option<Vec<u8>>

Read-only view. For the reserved key "agentWallet" the contract MUST return the current agent_wallet value (if Some) serialised as the AccountAddress byte form; otherwise look up key in the agent’s on_chain_metadata map.

agentWallet — reserved metadata key¶

The key "agentWallet" is reserved. setMetadata with this key MUST reject with Reject Codes — callers MUST use setAgentWallet instead, which carries the required cryptographic proof.

agentOf¶

// parameter: AgentTokenId
// returns:   Option<AgentView>

Read-only. Returns the full AgentView (returned) for the given token id, with owner_account derived from the CIS-2 ownership state. Returns None if no agent exists.

agentByExternalReference¶

// parameter: ExternalReference
// returns:   Option<AgentView>

Read-only. Looks up via refs_index keyed by (namespace, bytes) extracted from the supplied external_reference.kind, returning the full AgentView (returned) or None.

getAgentWallet¶

// parameter: AgentTokenId
// returns:   Option<AccountAddress>

Read-only. Returns Some(addr) when agent_wallet is set (after register or setAgentWallet), None otherwise (after transfer or revoke).

isActive¶

// parameter: AgentTokenId
// returns:   bool

Convenience read-only wrapper: true if the agent exists and status == Active; false otherwise.

transfer (CIS-2) — dual-reset hook¶

The CIS-2 transfer entrypoint MUST run two CIS-8004-specific hooks in addition to the standard CIS-2 ownership move:

  1. Clear ``external_reference``. If the agent had a Some external_reference, set it to None and release the refs_index entry. Emit ExternalReferenceSet (tag 242) with external_reference = None.

  2. Reset ``agent_wallet``. If the agent had a Some agent_wallet, set it to None. Emit AgentWalletSet (tag 245) with new_wallet = None.

Both reset events MUST be emitted before the standard CIS-2 Transfer event for the same token. The new owner MUST re-establish external_reference via setExternalReference and agent_wallet via setAgentWallet if they want the agent to be re-bound and re-payable.

The remaining CIS-2 entrypoints (balanceOf, operatorOf, updateOperator, tokenMetadata) follow the standard CIS-2: Concordium Token Standard 2 semantics with no CIS-8004-specific augmentation. tokenMetadata(token_id) MUST return the agent’s agent_uri as the CIS-2 MetadataUrl.url.

supports¶

A CIS-8004 contract MUST implement CIS-0: Standard Detection and MUST return Support for CIS-0, CIS-2, and CIS-8004.

Departures from ERC-8004 v2¶

This section is informative.

  • CIS-8004 has native ``revoke``. ERC-8004 v2 has no native revocation primitive; CIS-8004 provides one because soft-deactivation without burning the NFT is the more common Concordium-ecosystem need.

  • ``agent_wallet`` resets on transfer. The new owner MUST explicitly re-establish agent_wallet via setAgentWallet. This mirrors ERC-8004 v2 semantics.

  • ``external_reference`` resets on transfer. The new owner MUST re-establish their own external_reference; previous bindings are released from refs_index. This is stricter than the ERC-8004 v2 spec, which is silent on the question.

  • Identifier form is CIS-2 token address (Base58Check), not URI/DID. Off-chain consumers receive a single canonical Base58Check string derived from (contract, token_id).

  • Reputation Registry and Validation Registry components of ERC-8004 v2 are out of scope for this version.

Security Considerations¶

Dual authorisation on setAgentWallet

Both the current owner AND the new wallet’s controller must authorise — protecting against either side unilaterally redirecting payments. The 26-byte CIS-8004/v1/setAgentWallet prefix and the contract_address + genesis_hash pinning prevent cross-context signature replay.

Transfer hook resets

Both external_reference and agent_wallet are reset on every transfer. This prevents a previous owner’s payment address or external identity binding from accidentally persisting under new ownership. The new owner MUST explicitly re-establish each.

CIS-2 contract recipients

transfer.to MAY be a contract address per CIS-2. Implementations SHOULD consider whether contract-owned agents are meaningful for their use case — agent NFTs held by a contract have no direct CIS-2 signature channel for re-setting agent_wallet, so the agent would be unable to receive payments routed through that field until transferred back to an account.
